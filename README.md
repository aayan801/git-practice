\# Things You Should Never Do: Rewriting Code From Scratch



\*\*Article:\*\* \[Things You Should Never Do, Part I](https://www.joelonsoftware.com/2000/04/06/things-you-should-never-do-part-i/) by Joel Spolsky



\## Why I Found It Interesting



Spolsky argues that throwing away a working codebase to rewrite it from scratch is

one of the worst strategic mistakes a software company can make, using Netscape's

rewrite as the cautionary tale. His core point is that old, "messy" code usually

isn't messy for no reason: each odd-looking conditional is often a fix for a

real-world bug that a rewrite will have to rediscover the hard way.



What stuck with me is how counterintuitive this is as a student. Every assignment

starts from a blank file, so a clean rewrite feels faster than slowly refactoring.

The article reframes existing code as \*accumulated knowledge\* rather than debt,

which changes how I think about working in large, older codebases.
